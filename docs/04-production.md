# Phase 3–4 — Storyboard & Image Production

## Pipeline
```
source/Chapter_XX.md  ──(adapt)──▶  content/storyboards/epXX.js   (Phase 3: scenes, panels, camera, dialogue, source line refs)
                                         │
                       node scripts/render-art.js                  (Phase 4: renders every panel)
                                         ▼
art/out/epXX/pNN.svg  +  meta.json (panel size, speaker positions, dialogue)
docs/storyboards/epXX.md                                            (human-readable storyboard, generated)
                                         │
                       node scripts/seed.js --publish               (imports into DB + file storage, places Thai text)
                                         ▼
                                   website / admin
```

## Image production (Phase 4) — วิธีการและข้อจำกัดที่ต้องทราบ
- ในสภาพแวดล้อมที่ใช้ผลิตงานนี้ **ไม่มีโมเดลสร้างภาพที่สามารถรักษาหน้าตาตัวละครให้เหมือนเดิมได้ตลอด 400+ ช่อง** จึงผลิตภาพด้วย
  **เอนจินวาดภาพเวกเตอร์ที่เขียนขึ้นเฉพาะงานนี้** (`art/lib/`): ตัวละครเป็นหุ่นโครงร่าง (rig) ที่มีมุมข้อต่อ, ใบหน้า/ทรงผม/สีตา/ชุดกำหนดไว้ที่เดียว,
  ฉากหลัง 30 แบบตามสถานที่ในต้นฉบับ, เอฟเฟกต์ (ลำแสง, เลือด, สัญลักษณ์รีเซ็ต 10 วินาที, หมอก, เส้นใยพลังงาน ฯลฯ)
- ผลลัพธ์เป็นภาพ Webtoon จริงทุกช่อง (SVG) แต่ **สไตล์เป็นภาพแฟลตเรียบง่าย** ไม่ใช่งานวาดมือ/เพนต์ระดับมืออาชีพ — ท่าทางบางช่องยังแข็ง
- ข้อดีของวิธีนี้: ความต่อเนื่องของหน้าตา เสื้อผ้า บาดแผลถูกควบคุมด้วยข้อมูล (ดู 03-continuity.md) และแก้ไข/วาดใหม่ทั้งเรื่องได้ด้วยคำสั่งเดียว
- **ไม่มีข้อความภาษาไทยในภาพ** (ตรวจอัตโนมัติ) — ข้อความทั้งหมดถูกวางทับโดยเว็บไซต์ ข้อความในภาพมีเพียงป้ายร้าน "DEAD-END" ตามต้นฉบับ
- ฉากรุนแรง (การยิงชายชราและเด็ก, การตายของพ่อค้าชรา) ถูกนำเสนอแบบไม่โจ่งแจ้ง (ตัดภาพ/แสงกลบ) โดยไม่เปลี่ยนเหตุการณ์
- หากต้องการยกระดับภาพเป็นงานวาดมือ: ใช้ Storyboard + Character Sheet เป็นบรีฟ แล้วอัปโหลดภาพใหม่แทนที่ทีละช่องผ่าน Admin (ปุ่ม "เปลี่ยนภาพของ Panel นี้") — ตำแหน่งข้อความเดิมยังอยู่

## Thai text placement
ตำแหน่ง Speech Bubble เริ่มต้นคำนวณอัตโนมัติจากตำแหน่งศีรษะผู้พูด และ **วัดขนาดข้อความจริงด้วยฟอนต์เดียวกับเว็บไซต์ในเบราว์เซอร์** (`scripts/measure.js`)
ทั้งที่ความกว้างเดสก์ท็อปและมือถือ จากนั้นจัดไม่ให้ทับกัน/ล้นขอบ (ย่ออักษรเล็กน้อยเฉพาะช่องที่แน่นมาก)
ผลตรวจ `scripts/bubble-audit.js`: 854 กล่อง ไม่ทับกันและไม่ล้นขอบ ที่ความกว้าง 360 / 390 / 720 / 1200 px
ข้อจำกัด: ช่องที่บทพูดยาวมาก กล่องข้อความอาจบังตัวละครบางส่วน — ปรับได้ใน Admin
